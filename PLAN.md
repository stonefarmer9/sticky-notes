## Decisions

- NoteId is a branded string generated with crypto.randomUUID().
- Note has flat x, y, width, height fields.
- NoteColor is a string-literal union.
- DEFAULT_NOTE_SIZE is 200×200.
- Double-clicking the board creates a note centered on the pointer, clamped to the board and focused for text editing.
- Before the Board and Note rendering step, add @testing-library/react, @testing-library/jest-dom and jsdom, plus a jsdom test config in vite.config.ts.
- Board-dependent actions (CREATE_NOTE, MOVE_NOTE, RESIZE_NOTE) carry a `board: Size` payload and the reducer clamps with geometry, so the reducer stays pure and enforces layout invariants in one place.
- CREATE_NOTE carries the id (generated by the caller) so the reducer stays deterministic; the reducer assigns zIndex as top + 1.
- Reducer returns the same state reference when nothing changes (unknown id, note already on top) to skip re-renders.
- `strict` and `noUncheckedIndexedAccess` live in tsconfig.app.json and tsconfig.node.json; compilerOptions in the root tsconfig are not inherited by project references.
- user-event is included for component tests because it makes interaction tests (double-click, typing) much simpler. Drag and resize tests use `fireEvent` with `PointerEvent`, plus a stub for `setPointerCapture`.
- README is updated as part of each milestone (see AGENTS.md): decisions, feature table and *(planned)* markers change before the milestone is ticked.
- Creation is double-click only, at the default 200×200; there is no size input. Every note is resizable by dragging a single bottom-right corner handle.
- The board fills the window with a 1024×768 minimum; its size is read at interaction time and not stored in state.
- Prettier owns formatting (single quotes, semicolons, trailing commas, width 100). `format:check` is part of `verify`. Markdown, `Design/` and `.opencode/` are ignored so README and PLAN conventions are not rewritten.
- Notes are positioned with `transform: translate3d` and stacked with CSS `z-index`, so bringing to front never reorders the DOM; colors come from a typed `Record<NoteColor, string>` in `styles/noteColors.ts`.

- Tests are checked by mutation (break the code, a test must fail) before a milestone is ticked. Do not write tests for features that do not exist yet.
- Board subscribes to the whole state; per-frame gesture updates must bypass the reducer (direct style updates), commit on pointerup.

- Focusing a newly created note for text editing waits for the edit-text milestone; there is no editable field to focus yet.
- Tests for pointer coordinates use `fireEvent` with a `stubBounds` helper because jsdom has no layout.

- `useDrag` keeps the gesture in a ref and writes `transform` directly once per frame; it commits `MOVE_NOTE` once on pointerup and skips the commit when the position did not change. Note receives stable callbacks from Board, so it stays presentational.
- Bring to front happens on pointer down (not on pointer up), so a press alone raises a note.
- Trash feedback will need a per-frame callback from `useDrag` (position while dragging); add it when the trash milestone needs it, not before.
